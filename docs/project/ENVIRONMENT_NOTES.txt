# Codex 项目构建前环境与执行约束

你现在需要在我的 Windows 本地开发环境中，从零构建一个：

Tauri + Rust + SQLite + 可插拔 Embedding 接口 + 本地 Vector Retrieval + 简单 RAG

的“证券 PC 端侧轻量化本地知识库原型 Demo”。

本文件只描述：

1. 当前开发环境；
2. 项目目录；
3. 已安装和未安装的依赖；
4. Codex 可以做什么；
5. Codex 不应该做什么；
6. 构建过程中的执行规则。

具体业务和架构需求以另一份《项目构建完整需求》为准。

==================================================

即使目前没有真实 Embedding，

项目也必须能够：

写入 KnowledgeBase
写入 Document

查询 Vector
删除 Vector
更新 Index 状态

==================================================
十二、Vector Store
==================================================

第一版目标：

SQLite + sqlite-vec

但是：

必须定义 VectorStore Trait。

业务层禁止直接依赖 sqlite-vec API。

如果当前 Windows + Rust + sqlite-vec 版本出现兼容问题：

1. 优先查询当前官方文档；
2. 尝试稳定方式完成；
3. 如果确实无法完成，
   保留 VectorStore 抽象；
4. 可以临时使用 SQLite BLOB 保存向量 +
   Rust 内存 cosine similarity 做最小可运行实现；
5. 但必须记录为 fallback；
6. 不允许把整个项目停掉。

优先目标：

SQLite 数据库链路必须跑通。

==================================================
十三、非常重要：本期不要接真实 Embedding
==================================================

当前项目不要下载、不要集成、不要调试任何真实 Embedding 模型。

包括但不限于：

Hugging Face Embedding
ONNX Embedding

不要安装：

ONNX Runtime
PyTorch
Python AI Runtime
CUDA
cuDNN

真实 Embedding 由另外一名成员负责。

你的任务是：

把 Embedding 的“插槽”做好。

必须提供：

EmbeddingProvider Trait

EmbeddingAdapter

EmbeddingRegistry

EmbeddingInput

EmbeddingOutput

EmbeddingModelInfo

VectorIngestService

让外部 Embedding 模块以后能够：

接收 Chunk
→ 输出 Vector
→ 交给当前项目
→ 写入 SQLite
→ 建立检索索引

==================================================
十五、Embedding 对接原则
==================================================

业务系统不能假设：

Vector 是 512 维

Vector 是 768 维

Vector 是 1024 维

业务系统不能假设：

CLS Pooling

Mean Pooling

Normalize=true

固定 Query Prefix

固定模型 Runtime

这些都由外部 Embedding Adapter 描述。

当前框架只要求外部最终能够提供：

model_id
model_version
dimension
embedding_config_hash
vector

Document Vector 还需要：

chunk_id

Query Vector 需要：

query_id 或 request_id

==================================================
十九、开发执行原则
==================================================

先读取：

1. 本环境说明
2. 项目构建完整需求

然后：

先输出：

1. 最终目录结构；
2. Rust crate 清单；
3. npm dependency 清单；
4. SQLite 设计；
5. Embedding 对接接口；
6. 开发阶段顺序。

随后立即开始创建项目。

不要等我再次确认。

每完成一个阶段：

尽量执行：

cargo check
cargo test
npm.cmd run build

必要时：

npm.cmd run tauri dev

能自行解决的问题：

自行修复继续。

只有以下情况再停下来：

涉及删除 D:\Workspace 之外的文件；
涉及危险系统级配置；
必须提供真实账号/API Key；
需求本身发生冲突且无法自行选择。
