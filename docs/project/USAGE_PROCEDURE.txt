# 历史原始资料：其中的旧原型路径已失效，当前操作流程请以仓库根目录 README.md 为准。

完整流程如下。`D:\Workspace\knowledge_base\test_docs` 可以直接使用，不需要复制到 `sample_docs`。

## 1. 创建或选择知识库

进入左侧“知识库”：

- 名称：自行填写
- 本地目录：

```text
D:\Workspace\knowledge_base\test_docs
```

- 点击“创建”

同一个目录只需要创建一次。如果再次用同一路径创建，会出现：

```text
UNIQUE constraint failed: knowledge_base.root_path
```

遇到这种情况，直接在右侧知识库列表中选择已有知识库即可。

## 2. 扫描文件并生成 Chunk

进入左侧“文件”，点击“重新扫描”。

当前支持的主要文件类型是：

- `.md`
- `.txt`

扫描会完成：

```text
读取文件 → 计算文件 Hash → 提取文本 → 按 Chunk Size 切分 → 写入 SQLite
```

### 怎么确认已经生成 Chunk？

有两个地方可以看。

在“文件”页面的表格里查看“Chunk / Vector”列。例如：

```text
8 / 0
```

代表：

- `8`：该文件已经切成 8 个 Chunk
- `0`：这 8 个 Chunk 还没有生成向量

也可以进入“Embedding”页面，在底部查看：

```text
待对接 Chunks（N）
```

里面会展示：

- Chunk ID
- 文件名
- Chunk 序号
- 前一部分文本内容

例如：

```text
risk.md · #0
risk.md · #1
risk.md · #2
```

看到这些内容，就说明 Chunk 已成功写入 SQLite。

如果显示 `待对接 Chunks（0）`，检查：

- 是否已经点击“重新扫描”
- 目录中是否有 `.md` 或 `.txt`
- 当前右上角选择的是不是正确知识库
- 文件是否为空

## 3. 启动 Embedding 服务

进入左侧“Embedding”，点击“启动服务”。

正常状态应该显示：

```text
RUNNING
由应用管理 · PID ...
Python 依赖：已安装
协议：1
```

“已加载”一开始可能显示：

```text
无（模型按需加载）
```

这是正常的。模型会在第一次建立索引或第一次调用时加载。

## 4. 选择模型并建立向量索引

在“建立真实向量索引”区域选择模型，例如：

```text
BAAI/bge-small-zh-v1.5 · 512d
```

然后点击：

```text
为全部 Chunk 建立索引
```

第一次执行可能会稍慢，因为 Python 需要从本地模型目录加载模型。

完成后，在 `Embedding Profiles` 中应该看到：

```text
model_id    bge-small
status      INDEXED
vectors     8
```

理想情况下：

```text
vectors 数量 = Chunk 数量
```

例如文件页面原来显示：

```text
8 / 0
```

完成索引后重新进入“文件”页面，应显示：

```text
8 / 8
```

这表示文本切分和向量化均已完成。

如果切换到 `m3e-base` 或 `bge-m3`，需要先下载并配置对应模型，然后为该模型重新建立一套向量索引。不同模型的向量不能混用。

## 5. 测试向量检索

进入左侧“向量检索”：

1. 选择“真实 Embedding”
2. 选择刚才建立索引时使用的同一个模型
3. 输入问题
4. 设置 `Top-K`，建议先用 `5`
5. 点击“搜索”

例如：

```text
投资组合的主要风险控制原则是什么？
```

结果会显示：

- 来源文件
- 相似度分数
- 命中的 Chunk 内容
- Chunk ID 和序号

这里能够成功返回结果，就说明以下链路已经跑通：

```text
问题
 → Query Embedding
 → SQLite 向量检索
 → Top-K Chunk
```

如果提示该模型没有向量，通常是因为搜索时选择的模型与建立索引时选择的模型不一致。

## 6. 使用 DeepSeek 进行 RAG 问答

确认 [`.env`](D:/Workspace/local-kb/.env) 至少配置：

```env
LOCAL_KB_LLM_BASE_URL=https://api.deepseek.com
LOCAL_KB_LLM_MODEL=deepseek-v4-flash
DEEPSEEK_API_KEY=你的真实Key
```

还需要确保：

```powershell
Test-NetConnection api.deepseek.com -Port 443
```

结果是：

```text
TcpTestSucceeded : True
```

然后进入“RAG 问答”：

1. 选择“真实 Embedding”
2. 选择与建立索引相同的模型
3. 输入问题
4. `Top-K` 建议先设置为 `5`
5. 点击“发送”

完整调用过程是：

```text
用户问题
 → 本地 Embedding
 → 本地 SQLite 向量检索
 → 取得 Top-K Chunk
 → 拼装 Context
 → 调用 DeepSeek
 → 显示回答和本地资料来源
```

Embedding 和向量检索都在本地运行，但命中的 Chunk 内容会发送给 DeepSeek。

## 7. 文件发生变化之后

如果修改、增加或删除了知识库目录里的文件：

1. 进入“文件”
2. 点击“重新扫描”
3. 检查新的 Chunk 数量
4. 回到“Embedding”
5. 使用原来的模型重新点击“为全部 Chunk 建立索引”
6. 再进行检索或 RAG 问答

文件变化后旧向量可能被删除或标记为 `STALE`，因此需要重新建立索引。

最简使用顺序就是：

```text
创建/选择知识库
 → 重新扫描
 → 确认 Chunk 数量大于 0
 → 启动 Embedding 服务
 → 选择模型
 → 建立真实向量索引
 → 确认 Vector 数量等于 Chunk 数量
 → 向量检索
 → RAG 问答
```
