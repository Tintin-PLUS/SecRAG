# 评测说明

正式评测入口：`eval/eval_search.py`。运行命令统一见[README](../README.md#5-终端三运行评测)。

## 测什么

当前题集`eval/test_queries.json`有34个问题，样例资料在`test_docs/`。默认比较`bge-small`、`m3e-base`、`bge-m3`，也可只测一个模型。

流程：清空本子项目的实验数据库记录 → 使用指定模型重新导入样例 → 对34个问题逐个请求`/api/search` → 打印指标和逐题结果。

检索方式为向量检索与BM25关键词检索的融合排序，不能把结果称为“纯向量模型准确率”。本项目与`local-kb`桌面Demo的切块、检索实现不同，结果不能直接替代桌面Demo测试。

## 指标

| 输出 | 具体含义 |
|---|---|
| Hit@3 | 前3个片段中至少1个满足题目关键词规则的问题比例 |
| MRR | 仅检查前3名，应在正式报告中标MRR@3；第一条相关结果的排名倒数均值，不是平均排名 |
| Latency | HTTP搜索请求发起到响应读取/JSON解析后的平均耗时；含问题向量化、混合检索及通信，不含资料导入和LLM生成 |

相关性判断：片段包含`must_contain`的全部词，并包含`any_of`中的至少一个词（该列表非空时）。这是自动关键词规则，不代表逐题经过人工审核，也不一定核对公司和日期。

## 复现与限制

- **每次运行会删除`data/knowledge.db`中的chunks/documents记录。** 只用于这个独立评测数据库，不要保存自己的业务资料，也不要指向`local-kb/data`。
- 必须从`embedding-test`目录运行，脚本和服务使用相对路径。
- 脚本会跳过请求异常；HTTP返回业务错误也可能被当成没有命中。报告应核对成功问题数和错误输出。
- 文档导入流程对部分失败处理较宽松；导入日志中的success不单独证明所有向量生成成功。
- 当前每题请求一次，未专门预热、未计算P95，也没有记录硬件和内存。不要将其描述为完整性能测试。
- 服务会缓存已经加载的模型，未固定CPU/GPU和线程；在正式比较中应记录实际设备，必要时分模型重新启动。
- 评测输出默认只打印到终端。README提供保存到`results/`的方法；该目录不上传Git。
- 如需精确复现模型，需另行记录模型缓存对应的提交号、软件依赖版本、数据版本和机器配置；原版脚本未提供`--revision`参数。
- 现有样例中的财务数据未在本次整理中验证真伪，仅作程序测试输入，不用作投资分析结论。

## 本次原版结构复测（2026-09-06）

Windows、Python 3.12.8、sentence-transformers 5.7.0、PyTorch 2.14.0（CPU），Rust 1.98.1 release 构建。模型用原版 `scripts/embed.py` 准备到用户默认缓存，原版 `embed_server.py` 离线加载；两个模型共用同一服务进程依次评测。

| 模型 | 完成题数 | Hit@3 | MRR@3 | 平均 Latency |
|---|---:|---:|---:|---:|
| bge-small | 34/34 | 88.2% | 0.7157 | 87 ms |
| m3e-base | 34/34 | 85.3% | 0.7255 | 101 ms |

每轮均导入 12 份资料、78 个片段；另核对了 M3E 评测后的数据库：78 条向量均为有效的 768 维数组，并核对 BGE-small 接口能返回有效的 512 维向量。原始输出在本机 `results/original-bge-small-20260906.txt` 和 `results/original-m3e-base-20260906.txt`；环境信息与依赖版本同在 `results/`，均由 Git 忽略。

本次两个模型的命中率、MRR@3 与历史截图一致，耗时不一致；耗时是本机本轮结果，不是性能保证。BGE-M3 本次未测试。此轮用于确认目录整理后仍能运行，完整技术选型还需补充多轮性能和资源占用测试。
